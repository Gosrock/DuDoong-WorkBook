# 배포 구조

## 전체 아키텍처

```
Internet → AWS ALB/CloudFront (SSL termination)
         → EC2 (ap-northeast-2)
         → Nginx:80 (host networking, 리버스 프록시)
            ├── /api/*     → API Server (localhost:8080)
            ├── /          → Ticket App (localhost:3000)
            └── /admin/*   → Admin Panel (localhost:3100)
         → Redis:6379 (localhost)
         → MySQL (AWS RDS, 외부)
```

---

## 서비스 포트 배치

| 서비스 | 포트 | 기술 | 비고 |
|--------|:----:|------|------|
| Nginx (리버스 프록시) | 80 | Nginx 1.21.4 | 엔트리 포인트 |
| API Backend | 8080 | Spring Boot (Java 17) | REST + WebSocket |
| Ticket App | 3000 | Next.js | 관객용 프론트엔드 |
| Admin Panel | 3100 | React (Vite) | 호스트용 프론트엔드 |
| Socket Server | 8090 | Spring WebSocket | STOMP 실시간 |
| Redis | 6379 | Redis Alpine | 캐시/세션/분산락 |

> 모든 서비스 `network_mode: "host"` 사용 (Docker bridge 아님)

## CI/CD 파이프라인

### 태그 컨벤션
| 서비스 | 태그 형식 | 예시 |
|--------|----------|------|
| Backend API | `Api-v*.*.*` | `Api-v1.0.7` |
| Backend Batch | `Batch-v*.*.*` | `Batch-v1.0.1` |
| Backend Socket | `Socket-v*.*.*` | `Socket-v1.0.1` |
| Frontend Ticket | `Ticket-v*.*.*` | `Ticket-v1.3.1` |
| Frontend Admin | `Admin-v*.*.*` | `Admin-v1.1.2` |

### 백엔드 이미지 빌드 파이프라인
```
1. 태그 push (예: Api-v1.0.7) → GitHub Actions 트리거
2. Java 17 (Corretto) 셋업
3. 로컬 Redis docker-compose up (테스트용)
4. ./gradlew :DuDoong-Api:build (테스트 포함)
5. Docker Hub 로그인
6. Docker 이미지 빌드 & push
```

### 프론트엔드 이미지 빌드 파이프라인
```
1. 태그 push (예: Ticket-v1.3.1) → GitHub Actions 트리거
2. .env 파일 생성 (GitHub Secrets)
3. Docker Buildx 셋업 (linux/amd64)
4. Docker Hub 로그인
5. 멀티 플랫폼 빌드 & push
```

### 배포 파이프라인 (DuDoong-Deploy)
```
1. main 브랜치 push → deploy.yml 트리거
2. .env 파일 생성 (secrets.ENV_VARS)
3. SSH로 서버 접속
4. docker-install.sh 실행 (Docker 설치 확인)
5. rsync로 파일 동기화
6. docker-compose pull → up --build -d
7. 이전 이미지 정리 (prune)
```

### 배포 환경
- **스테이징**: main 브랜치 push 시 자동 배포
- **프로덕션**: 스테이징 완료 후 연쇄 배포 또는 수동 트리거 (`deploy-live.yml`)

## 환경 변수 구조

### 공통
- `TZ=Asia/Seoul`
- `SPRING_PROFILES_ACTIVE` (dev/staging/prod)

### 백엔드 주요 환경변수
| 카테고리 | 변수명 |
|----------|--------|
| JWT | `JWT_SECRET_KEY`, `JWT_ACCESS_EXP`, `JWT_REFRESH_EXP` |
| OAuth | `KAKAO_CLIENT`, `KAKAO_SECRET`, `KAKAO_REDIRECT`, `KAKAO_APP_ID`, `KAKAO_ADMIN_KEY` |
| PG | `TOSS_PAYMENTS_KEY`, `TOSS_MID` |
| AWS | `AWS_ACCESS_KEY`, `AWS_SECRET_KEY`, `AWS_S3_BUCKET`, `AWS_S3_BASE_URL` |
| Redis | `REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD` |
| Slack | `SLACK_WEBHOOK_TOKEN`, `SLACK_WEBHOOK_ID`, `SLACK_SERVICE_CHANNEL_ID` |
| NCP | `NCP_SERVICE_ID`, `NCP_ACCESS_KEY`, `NCP_SECRET_KEY`, `NCP_PLUS_FRIEND_ID` |
| 보안 | `ACL_WHITELIST`, `SWAGGER_USER`, `SWAGGER_PASSWORD` |

### 시크릿 관리
- GitHub Secrets → 배포 시 `.env` 파일 생성
- 코드/이미지에 시크릿 포함하지 않음

## 멀티모듈 Dockerfile 구조

### Backend (Java 17 + Alpine)
```dockerfile
FROM openjdk:17-ea-slim
COPY build/libs/*.jar app.jar
ENTRYPOINT ["java", "-Dspring.profiles.active=${SPRING_PROFILES_ACTIVE}", "-jar", "app.jar"]
```

### Frontend Ticket (Next.js)
```dockerfile
FROM node:18-alpine AS builder
# ... build ...
FROM node:18-alpine
# Next.js 서버 실행
```

### Frontend Admin (Vite → Nginx)
```dockerfile
FROM node:18-alpine AS builder
# ... build ...
FROM nginx:1.19.0
COPY --from=builder /app/dist /usr/share/nginx/html
```
