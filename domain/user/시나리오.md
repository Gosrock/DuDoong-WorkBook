# 유저/인증 도메인 - UseCase 시나리오

## UC-U01: 카카오 회원가입

**Actor**: 비로그인 사용자
**선행조건**: 카카오 계정 보유

### 정상 플로우
1. 카카오 로그인 버튼 클릭
2. `GET /auth/oauth/kakao/link` → 카카오 인증 URL 획득
3. 카카오 인증 완료
4. `GET /auth/oauth/kakao?code={code}` → id_token 검증
5. 신규 유저 확인 → 회원가입 폼 표시
6. 이름, 이메일, (선택) 전화번호 입력
7. `POST /auth/oauth/kakao/register` → 유저 생성
8. JWT 발급 (Access + Refresh Token)

### 예외 플로우
- 동일 oid 동시 가입 → Redisson 분산락으로 차단
- 카카오 id_token 검증 실패 → 401

## UC-U02: 로그인

**Actor**: 기존 회원

### 정상 플로우
1. 카카오 인증 완료
2. id_token에서 oid 추출 → 기존 유저 조회
3. `POST /auth/oauth/kakao/login`
4. JWT 발급, `lastLoginAt` 업데이트

### 예외 플로우
- DELETED 유저 → 403
- FORBIDDEN 유저 → 403

---

## UC-U03: 토큰 갱신

**Actor**: 인증된 사용자 (Access Token 만료)

### 정상 플로우
1. Access Token 만료 감지
2. `POST /auth/token/refresh` (Refresh Token 전달)
3. Refresh Token 유효성 확인 (Redis 조회)
4. 새 Access Token 발급
5. `lastLoginAt` 업데이트

### 예외 플로우
- Refresh Token 만료/미존재 → 401 → 재로그인 필요

---

## UC-U04: 회원 탈퇴

**Actor**: 로그인한 사용자

### 정상 플로우
1. `DELETE /auth/withdraw`
2. Redis: Refresh Token 삭제
3. DB: accountState → `DELETED`, 프로필 마스킹
4. DB: oid → `DELETED:{timestamp}:{oid}`
5. 카카오: `unlinkUser` API 호출

### 후처리
- 승인 대기 주문 → 자동 거부
- 이후 동일 카카오 계정으로 **재가입 가능** (oid 변경으로 충돌 없음)

---

## UC-U05: 로그아웃

**Actor**: 로그인한 사용자

### 정상 플로우
1. `POST /auth/logout`
2. Redis: Refresh Token 삭제
3. 쿠키에서 Access Token 제거

---

## 문의 대응 가이드

### "로그인이 안 돼요"
1. 카카오 계정 상태 확인
2. 유저 상태 확인 (DELETED/FORBIDDEN이면 로그인 불가)
3. 탈퇴 후 재가입인 경우 → 새 계정으로 가입 안내

### "탈퇴했는데 다시 가입하고 싶어요"
- 동일 카카오 계정으로 재가입 가능 (oid 변경으로 기존 데이터와 분리)
- 이전 예매 내역/티켓은 복구 불가

### "다른 사람이 내 계정을 사용한 것 같아요"
- HttpOnly 쿠키 미적용으로 XSS 취약점 존재 → 비밀번호 변경(카카오), 재로그인 안내
