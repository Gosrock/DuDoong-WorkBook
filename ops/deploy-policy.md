# 배포 정책

> 최종 수정: 2026-03-15

---

## 1. 배포 프로세스 개요

```
코드 작성 → PR 생성 → 코드 리뷰 → PR 머지 → CI/CD 자동 빌드
→ 스테이징 배포 → 스테이징 검증 → 프로덕션 배포
```

| 환경 | 브랜치 | 목적 |
|------|--------|------|
| 스테이징 | `develop` | 기능 검증, QA |
| 프로덕션 | `main` | 실사용자 서비스 |

---

## 2. 배포 전 체크리스트

### PR 머지 전

- [ ] 코드 리뷰 승인 (최소 1명, 핫픽스 제외)
- [ ] CI 파이프라인 통과 (빌드 성공 + 테스트 통과)
- [ ] 충돌(conflict) 없음

### 스테이징 배포 후

- [ ] 스테이징 환경에서 핵심 기능 동작 확인 (예매, 결제, QR 입장)
- [ ] 에러 로그 이상 없음
- [ ] 영향 받는 기능 회귀 테스트 완료

### 프로덕션 배포 전

- [ ] 스테이징 검증 완료
- [ ] 배포 금지 시간대 해당 없음 (아래 참고)
- [ ] DB 마이그레이션이 있는 경우: 마이그레이션 스크립트 검토 완료
- [ ] 필요 시 팀 공지 (Slack 등)

---

## 3. 배포 금지 시간대

아래 시간대에는 원칙적으로 프로덕션 배포를 금지합니다.

| 금지 시간대 | 이유 |
|-------------|------|
| 금요일 오후 (17:00 이후) | 주말 장애 대응 인력 부재 |
| 공연 진행 중 (입장 시작 ~ 종료) | 티켓 입장 시스템 중단 위험 |
| 예매 오픈 직전/직후 1시간 | 트래픽 집중 구간 |
| 공휴일 및 연휴 전날 오후 | 장애 대응 어려움 |

> 긴급 장애 대응(핫픽스)은 예외로 적용됩니다.

---

## 4. 핫픽스 절차

서비스에 직접적인 영향을 주는 긴급 버그 발생 시 아래 절차를 따릅니다.

```
장애 확인 → hotfix 브랜치 생성 → 수정 → 리뷰 1명 승인
→ main 및 develop 동시 머지 → 즉시 프로덕션 배포 → 사후 공유
```

### 핫픽스 기준

- 서비스 전체 또는 핵심 기능 사용 불가 (결제, 입장 처리 등)
- 데이터 손실/오염 위험
- 보안 취약점 발견

### 핫픽스 시 완화 규칙

- 리뷰어 최소 1명으로 축소 가능
- 배포 금지 시간대 예외 적용
- 단, 빌드 + 핵심 기능 테스트는 반드시 통과

---

## 5. 롤백 절차

배포 후 서비스 이상이 감지되면 즉시 롤백을 시행합니다.

### 롤백 판단 기준

- 배포 후 5분 이내 에러율 급증
- 핵심 기능 장애 (결제 불가, 로그인 불가, 입장 불가)
- 모니터링 알림 발생 + 확인 불가 상황

### 롤백 실행 방법

```
1. 이전 안정 버전의 Docker 이미지 태그 확인
2. 해당 이미지로 서비스 재배포
3. 롤백 완료 후 서비스 정상 여부 확인
4. 원인 분석 후 수정 배포 준비
```

### 롤백 후 처리

- [ ] 롤백 완료 Slack 공지
- [ ] 원인 파악 시작
- [ ] 영향 받은 사용자 확인 (필요 시 CS 공지)
- [ ] 수정 후 재배포 계획 수립

---

## 6. 장애 대응 플로우

```
감지 → 알림 → 원인 파악 → 롤백/수정 → 서비스 정상화 → 포스트모템
```

| 단계 | 내용 | 담당 |
|------|------|------|
| **감지** | 모니터링 알림, 에러 로그 급증, CS 문의 폭증 | 자동/당직자 |
| **알림** | Slack 장애 채널에 상황 공유, 관련 팀원 호출 | 최초 발견자 |
| **원인 파악** | 로그 확인, 최근 배포 내역 확인, 영향 범위 파악 | 개발팀 |
| **롤백/수정** | 원인이 배포라면 즉시 롤백, 외부 장애라면 우회 처리 | 개발팀 |
| **서비스 정상화** | 정상 확인 후 Slack 공지, CS 안내문 작성 | 개발팀 + CS |
| **포스트모템** | 장애 원인, 영향 범위, 재발 방지 방안 문서화 | 개발팀 |

### 포스트모템 작성 기준

- 영향 사용자 50명 이상 또는 핵심 기능 30분 이상 장애 시 작성
- 작성 위치: `DuDoong-WorkBook/ops/postmortem/`
- 작성 시한: 장애 복구 후 48시간 이내
