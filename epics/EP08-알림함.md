# EP08: 알림함 기능

## 개요

마이페이지에서 접근하는 알림함. 예매/환불/공지 등 서비스 활동 알림을 모아 보는 인앱 알림 센터.
실제 카카오 알림톡 발송과는 별개로, **앱 내에서** 알림을 확인하는 기능.

## 읽음 처리

| 상태 | 표시 | 동작 |
|------|------|------|
| 안 읽음 | 굵은 글씨 + 파란 점 | 기본 |
| 읽음 | 일반 글씨 | 알림 클릭 시 자동 읽음 처리 |
| 전체 읽음 | - | "모두 읽음" 버튼 클릭 |

### 안 읽은 알림 뱃지

마이페이지 `🔔` 아이콘 옆에 안 읽은 알림 개수 빨간 뱃지 표시.

```
🔔 알림함  ●3      ← 안 읽은 알림 3개
```

## 데이터 모델

### Notification 엔티티

```kotlin
@Entity
@Table(name = "notification")
open class Notification(
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    val id: Long = 0L,

    @Column(nullable = false)
    val userId: Long,              // 수신자

    @Enumerated(EnumType.STRING)
    @Column(nullable = false)
    val type: NotificationType,    // 알림 종류

    @Column(nullable = false, length = 200)
    val title: String,             // 제목

    @Column(length = 500)
    val body: String? = null,      // 본문 (선택)

    @Column(nullable = false)
    var isRead: Boolean = false,   // 읽음 여부

    @Column(nullable = false)
    val createdAt: LocalDateTime = LocalDateTime.now(),

    // 클릭 시 이동할 대상
    @Enumerated(EnumType.STRING)
    @Column(nullable = false)
    val targetType: NotificationTarget,  // ORDER, EVENT, NOTICE, HOST

    @Column
    val targetId: Long? = null,    // 대상 ID (orderId, eventId, noticeId 등)
)

enum class NotificationType {
    // 관객
    ORDER_DONE,           // 예매 완료
    ORDER_CANCELED,       // 예매 취소/환불
    ORDER_APPROVED,       // 승인 완료
    ORDER_REJECTED,       // 승인 거절
    EVENT_REMINDER,       // 공연 임박 (D-1)
    NOTICE_NEW,           // 새 공지사항
    HOST_ANNOUNCEMENT,    // 호스트 공지

    // 호스트
    HOST_ORDER_RECEIVED,  // 예매 접수
    HOST_ORDER_REFUNDED,  // 환불 접수
    HOST_APPROVAL_REQUEST,// 승인 요청
    HOST_TICKET_SOLDOUT,  // 매진
    HOST_MEMBER_JOINED,   // 멤버 가입
}

enum class NotificationTarget {
    ORDER,    // → 주문 상세
    EVENT,    // → 공연 상세
    NOTICE,   // → 공지 상세
    HOST,     // → 호스트 관리
}
```

### DDL

```sql
CREATE TABLE notification (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id     BIGINT NOT NULL,
    type        VARCHAR(50) NOT NULL,
    title       VARCHAR(200) NOT NULL,
    body        VARCHAR(500),
    is_read     BOOLEAN NOT NULL DEFAULT FALSE,
    created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    target_type VARCHAR(20) NOT NULL,
    target_id   BIGINT,
    INDEX idx_notification_user_read (user_id, is_read, created_at DESC),
    INDEX idx_notification_user_created (user_id, created_at DESC)
);
```

## API 설계

### `GET /api/v1/notifications`
알림 목록 조회 (본인 알림만, 최신순)

**Request**
```
GET /api/v1/notifications?page=0&size=20
```

**Response**
```json
{
  "content": [
    {
      "id": 1,
      "type": "ORDER_DONE",
      "title": "고스락 정기공연 예매가 완료되었습니다",
      "body": "QR 코드를 미리 준비해주세요",
      "isRead": false,
      "createdAt": "2026-03-22T14:30:00",
      "targetType": "ORDER",
      "targetId": 10532
    }
  ],
  "page": 0,
  "size": 20,
  "totalElements": 15,
  "unreadCount": 3
}
```

**접근 권한**: USER (본인 알림만)

### `GET /api/v1/notifications/unread-count`
안 읽은 알림 수 조회 (뱃지용)

**Response**
```json
{
  "unreadCount": 3
}
```

### `PUT /api/v1/notifications/{notificationId}/read`
개별 알림 읽음 처리

### `PUT /api/v1/notifications/read-all`
전체 알림 읽음 처리

## 알림 생성 시점 (기존 이벤트 핸들러에 추가)

현재 이미 Spring Event로 비동기 처리하는 핸들러들이 있음. 여기에 알림 생성 로직만 추가.

| 기존 핸들러 | 이벤트 | 추가할 알림 |
|------------|--------|-----------|
| `DoneOrderEventAlimTalkHandler` | `DoneOrderEvent` | ORDER_DONE (관객) + HOST_ORDER_RECEIVED (호스트) |
| `WithDrawOrderEventAlimTalkHandler` | `WithDrawOrderEvent` | ORDER_CANCELED (관객) + HOST_ORDER_REFUNDED (호스트) |
| `RegisterUserEventAlimTalkHandler` | `UserRegisterEvent` | (없음 — 가입 환영은 알림함 불필요) |
| 신규 핸들러 필요 | 승인/거절 이벤트 | ORDER_APPROVED / ORDER_REJECTED |
| 배치 잡 추가 | D-1 배치 | EVENT_REMINDER |
| EP07 공지 생성 시 | 공지 생성 이벤트 | NOTICE_NEW (전체 유저) |

### 전체 유저 알림 (공지사항)

공지사항 등록 시 전체 유저에게 알림을 보내면 4만 건 INSERT가 됨. 이건 비효율적이므로:

**방법: 글로벌 알림 테이블 분리**

```sql
CREATE TABLE global_notification (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    type        VARCHAR(50) NOT NULL,   -- NOTICE_NEW
    title       VARCHAR(200) NOT NULL,
    body        VARCHAR(500),
    created_at  DATETIME NOT NULL,
    target_type VARCHAR(20) NOT NULL,
    target_id   BIGINT
);

CREATE TABLE global_notification_read (
    user_id         BIGINT NOT NULL,
    notification_id BIGINT NOT NULL,
    PRIMARY KEY (user_id, notification_id)
);
```

- 공지 1건 = `global_notification` 1행 INSERT
- 읽음 처리 시에만 `global_notification_read`에 INSERT
- 조회: 개인 알림 UNION 글로벌 알림 (LEFT JOIN read 테이블)

## 의사결정

| 결정 | 내용 | 이유 |
|------|------|------|
| 인앱 알림 only | 카카오 알림톡과 별개, 앱 내 알림함만 | 알림톡은 EP06 토큰 BM으로 분리 |
| 글로벌 알림 분리 | 공지사항은 별도 테이블 | 4만 유저에 개별 INSERT 방지 |
| 30일 보관 | 30일 지난 알림 자동 삭제 (배치) | DB 부담 경감 |
| 읽음만 저장 | 안 읽음이 기본, 읽으면 상태 변경 | 심플 |

## EP06 토큰 BM과의 관계

| 구분 | 알림함 (EP08) | 알림톡 토큰 (EP06) |
|------|-------------|------------------|
| 채널 | 앱 내 | 카카오톡 |
| 비용 | 무료 | 토큰 소비 |
| 트리거 | 자동 (이벤트 발생 시 항상) | 호스트가 ON/OFF 설정 |
| 용도 | 기본 알림 | 프리미엄 알림 |

알림함은 **기본 무료 알림**, 알림톡은 **유료 프리미엄 알림**으로 포지셔닝.
호스트 입장: "알림함은 공짜로 다 가는데, 카톡으로도 보내고 싶으면 토큰 써"
