## 1. Definition of Done (DoD)

모든 기능 개발은 아래 조건을 **모두** 충족해야 완료로 인정합니다.

### 개발 완료 기준

- [ ] 코드 리뷰 승인 (최소 1명)
- [ ] 빌드 성공 (CI 파이프라인 그린)
- [ ] 단위 테스트 통과
- [ ] 스테이징 환경에서 동작 확인
- [ ] 관련 문서 업데이트 (해당하는 경우)

### 배포 완료 기준

- [ ] 스테이징에서 핵심 플로우 회귀 테스트 완료
- [ ] 에러 로그 이상 없음
- [ ] 프로덕션 배포 후 5분간 모니터링 이상 없음

## 2. 핵심 플로우 회귀 테스트

기능 변경 시 반드시 아래 핵심 플로우를 확인합니다.

### 필수 테스트 플로우

| 플로우 | 테스트 항목 |
|--------|-------------|
| **예매 플로우** | 공연 조회 → 티켓 선택 → 주문 생성 → 결제 완료 → 티켓 발급 확인 |
| **결제 플로우** | 결제 수단 선택 → 결제 진행 → 성공/실패 처리 → 주문 상태 반영 |
| **QR 입장 플로우** | 티켓 QR 표시 → 스캔 → 입장 처리 확인 |
| **공연 등록 플로우** | 주최자 로그인 → 공연 생성 → 예매 오픈 설정 |
| **취소/환불 플로우** | 주문 취소 요청 → 취소 처리 → 환불 상태 확인 |

### 플로우별 우선순위

| 우선순위 | 플로우 | 이유 |
|----------|--------|------|
| P0 (항상) | 결제, QR 입장 | 매출/현장 운영 직결 |
| P1 (관련 변경 시) | 예매, 취소/환불 | 사용자 핵심 경험 |
| P2 (해당 시) | 공연 등록, 계정 | 주최자 운영 |

## 3. QA 환경

| 환경 | 브랜치 | 용도 |
|------|--------|------|
| **스테이징** | `develop` | 기능 검증, 통합 테스트, QA 진행 |
| **프로덕션** | `main` | 실사용자 서비스 (배포 후 모니터링) |

### 스테이징 환경 유의사항

- 실제 결제 연동은 테스트 모드로 운영 (실제 청구 없음)
- 테스트 계정으로만 접근 (실사용자 데이터 미사용)
- 스테이징 데이터는 주기적으로 초기화될 수 있음

## 4. 버그 심각도 분류

### 분류 기준

| 심각도 | 정의 | 예시 | 대응 속도 |
|--------|------|------|-----------|
| **Critical** | 서비스 전체 또는 핵심 기능 사용 불가 | 결제 전체 불가, 로그인 불가, QR 입장 불가 | 즉시 (핫픽스) |
| **Major** | 핵심 기능 오류 (우회 방법 없음) | 특정 결제 수단 오류, 티켓 미발급, 환불 처리 오류 | 당일 ~ 다음 배포 |
| **Minor** | 사용성 저하 (우회 방법 있음) | 필터 검색 오류, 알림 미발송, 일부 UI 동작 오류 | 다음 스프린트 |
| **Cosmetic** | UI/디자인 불일치 | 정렬 틀어짐, 텍스트 오탈자, 여백 이슈 | 여유 있을 때 |

### 버그 등록 시 포함 정보

```
- 심각도: [Critical / Major / Minor / Cosmetic]
- 발생 환경: [스테이징 / 프로덕션]
- 재현 단계: 1. ... 2. ... 3. ...
- 예상 결과:
- 실제 결과:
- 발생 빈도: [항상 / 간헐적]
- 스크린샷/로그: (첨부)
```

## 5. 릴리스 체크리스트

프로덕션 배포 전 최종 확인 목록입니다.

### 기능 검증

- [ ] 이번 릴리스에 포함된 기능 목록 확인
- [ ] 각 기능 스테이징 동작 확인 완료
- [ ] 핵심 플로우 회귀 테스트 완료 (예매, 결제, QR)
- [ ] Critical/Major 버그 모두 해결됨

### 기술 검증

- [ ] 빌드 성공 (최신 커밋 기준)
- [ ] 모든 테스트 통과
- [ ] DB 마이그레이션 스크립트 검토 완료 (해당 시)
- [ ] 환경변수/설정 변경 사항 적용 완료 (해당 시)

### 운영 준비

- [ ] 배포 금지 시간대 해당 없음
- [ ] 팀 공지 완료 (Slack)
- [ ] CS 팀 변경사항 공유 (사용자 영향 있는 경우)
- [ ] 롤백 시나리오 확인

### 배포 후

- [ ] 프로덕션 배포 완료 확인
- [ ] 5분간 에러 모니터링 이상 없음
- [ ] 핵심 기능 프로덕션 동작 확인 (예매, 결제 흐름)
- [ ] 배포 완료 Slack 공지

## 6. 테스트 범위 가이드

### 변경 유형별 테스트 범위

| 변경 유형 | 최소 테스트 범위 |
|-----------|-----------------|
| 결제 관련 변경 | 결제 전체 플로우 + 취소/환불 플로우 |
| 티켓 관련 변경 | 티켓 발급 + QR 입장 플로우 |
| 공연 관련 변경 | 공연 등록 + 예매 플로우 |
| 계정 관련 변경 | 로그인 + 예매 플로우 |
| DB 마이그레이션 | 전체 핵심 플로우 |
| 인프라/배포 변경 | 전체 핵심 플로우 |
| 단순 텍스트/UI 수정 | 해당 화면 확인 |
