# 정산(Settlement) 도메인 정책

## 2계층 구조

```
EventSettlement (이벤트 단위 정산)
    └── TransactionSettlement (거래 단위 정산)
            └── FeeDetail (수수료 상세)
```

---

## 이벤트 정산 상태 머신

```
READY ──► CALCULATED ──► ADMIN_CONFIRM ──► CLIENT_CONFIRM
```

| 상태 | 코드 | 설명 |
|------|------|------|
| 정산 대기 | `READY` | 이벤트 종료 후 초기 상태 |
| 계산 완료 | `CALCULATED` | 정산 금액 자동 계산 완료 |
| 관리자 확인 | `ADMIN_CONFIRM` | 두둥 관리자 확인 완료 |
| 호스트 확인 | `CLIENT_CONFIRM` | 호스트(클라이언트) 최종 확인 |

---

## 정산 금액 계산

```
총 매출 = 두둥티켓(APPROVED 주문) + 카드결제(CONFIRM 주문)

수수료 = PG 수수료 (토스페이먼츠) + VAT (PG 수수료 × 10%)

두둥 중개 수수료 = 현재 0원 (정책 미확정)

정산 금액 = 총 매출 - 수수료 - 두둥 수수료
```

---

## 정산 프로세스

> 출처: [두둥 정산 관련](../public-notion/두둥-정산-관련.md)

1. 이벤트 종료 후 **자동으로** 정산 작업 진행
2. 호스트 총 관리자(MASTER)의 이메일로 **정산서 전송**
3. 호스트 총 관리자가 정산서 확인 후 응답
4. 세금 계산서 발행을 위한 대표 개인 한명의 **통장 사본 요청**
5. 공연 종료 **6일 이후** 정산금액 지급 (일정 앞당겨질 수 있음)
6. 세금 계산서 발행

## 문의 대응 가이드

### "정산이 언제 되나요?"
- 공연 종료 6일 이후 지급
- 정산 상태 확인: `READY` → `CALCULATED` → `ADMIN_CONFIRM` → `CLIENT_CONFIRM`

### "정산 금액이 이상해요"
- PG 수수료 + VAT 차감 확인
- 환불/취소된 주문은 정산에서 제외
