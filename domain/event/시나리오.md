# 이벤트 도메인 - UseCase 시나리오

## UC-E01: 이벤트 생성

**Actor**: 호스트 매니저 이상
**선행조건**: 호스트 생성 완료

### 정상 플로우
1. 호스트가 이벤트 이름, 시작일시, 러닝타임을 입력
2. 시스템이 `endAt = startAt + runTime` 자동 계산
3. 이벤트 생성 (status = `PREPARING`)
4. `EventCreationEvent` 발행 → Slack 알림

### 예외 플로우
- 호스트 권한 부족 → 403

---

## UC-E02: 이벤트 기본 정보 수정

**Actor**: 호스트 매니저 이상

### 정상 플로우
1. 이벤트가 `PREPARING` 상태인지 확인
2. 이름/시작일시/러닝타임 수정
3. `EventContentChangeEvent` 발행

### 예외 플로우
- `OPEN` 상태에서 기본정보 수정 시도 → `CannotModifyOpenEventException`

---

## UC-E03: 이벤트 상세 정보 수정

**Actor**: 호스트 매니저 이상

### 정상 플로우
1. 상세 설명(content) 또는 이미지 수정
2. **OPEN 상태에서도 수정 가능**
3. `EventContentChangeEvent` 발행

### 핵심 규칙
- 포스터 이미지: S3 Presigned URL로 업로드
- 본문(content): LONGTEXT 타입, 길이 제한 없음

---

## UC-E04: 이벤트 오픈

**Actor**: 호스트 매니저 이상
**선행조건**: PREPARING 상태

### 정상 플로우
1. 오픈 조건 5가지 검증:
   - EventBasic 존재
   - EventPlace 존재
   - EventDetail 존재
   - TicketItem 최소 1개
   - startAt > 현재시간
2. status → `OPEN`
3. `EventStatusChangeEvent` 발행

### 예외 플로우
- 이미 OPEN 상태 → `AlreadyOpenStatusException`
- startAt이 과거 → `EventOpenTimeExpiredException`
- 필수 정보 미입력 → 오픈 불가

---

## UC-E05: 이벤트 삭제

**Actor**: 호스트 매니저 이상

### 정상 플로우
1. 삭제 가능 상태 확인 (PREPARING만)
2. 발급 티켓 존재 여부 확인
3. status → `DELETED` (Soft Delete)
4. `EventDeletionEvent` 발행

### 예외 플로우
- OPEN 상태에서 삭제 → `CannotDeleteByOpenEventException`
- 이미 삭제됨 → `AlreadyDeletedStatusException`
- 발급 티켓 존재 → 삭제 불가

---

## UC-E06: 정산 시작

**Actor**: 호스트 매니저 이상
**선행조건**: OPEN 상태

### 정상 플로우
1. status → `CALCULATING`
2. 정산 금액 자동 계산 시작
3. `EventStatusChangeEvent` 발행

---

## UC-E07: 이벤트 종료

**Actor**: 호스트 매니저 이상
**선행조건**: CALCULATING 상태

### 정상 플로우
1. 정산 완료 확인
2. status → `CLOSED`
3. `EventStatusChangeEvent` 발행

---

| 항목 | PREPARING | OPEN | CALCULATING | CLOSED |

| 러닝타임 | O | X | X | X |

| 이미지 | O | O | X | X |
| 티켓 추가 | O | O | X | X |
| 티켓 수정 | O | 제한적 | X | X |
| 삭제 | O | X | X | X |
