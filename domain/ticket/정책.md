# 티켓(TicketItem / IssuedTicket / Option) 도메인 정책

## 1. 티켓 상품 (TicketItem)

### 티켓 유형 매트릭스

3가지 지불 유형 x 2가지 승인 유형의 조합에 엄격한 제약이 있습니다.

#### PayType (지불 유형)

| PayType | 코드 | 가격 | 제약 |
|---------|------|------|------|
| 무료 티켓 | `FREE_TICKET` | 0원 강제 | - |
| 유료 티켓 | `PRICE_TICKET` | 최소 1,000원 | 선착순 필수, **제휴(partner) 호스트 필수** |
| 두둥 티켓 | `DUDOONG_TICKET` | 자유 | 승인형 필수, **계좌 정보 필수** |

#### ApproveType (승인 유형)

| ApproveType | 코드 | 설명 |
|-------------|------|------|
| 선착순 | `FIRST_COME_FIRST_SERVED` | 즉시 확정 (결제 완료 시) |
| 승인 | `APPROVAL` | 관리자 수동 승인 필요 |

#### 유효한 조합

| PayType | ApproveType | 가능 | 비고 |
|---------|-------------|:----:|------|
| FREE_TICKET | FIRST_COME | O | 일반 무료 |
| FREE_TICKET | APPROVAL | O | 승인형 무료 |
| PRICE_TICKET | FIRST_COME | O | **partner 호스트 필수** |
| PRICE_TICKET | APPROVAL | **X** | 유료+승인 조합 불가 |
| DUDOONG_TICKET | APPROVAL | O | **계좌 정보 필수** |
| DUDOONG_TICKET | FIRST_COME | **X** | 두둥+선착순 조합 불가 |

### 재고 관리

#### 이원 수량 관리
- `quantity`: 총 발행 수량
- `supplyCount`: 남은 수량 (차감/복구 추적)

#### 동시성 보호
- **Redisson 분산락**: 티켓 아이템 ID 기반 락
- 재고 차감: 주문 생성 시
- 재고 복구: 주문 취소/환불 시

### 구매 제한
- `purchaseLimit`: 1인당 최대 구매 수량
- 검증 시 기존 주문 수량 + 신규 수량 합산
- 승인형 주문은 대기 중 주문까지 포함하여 **보수적** 검사

### 티켓 수정/삭제 제약
- 판매 이력이 있는 티켓은 옵션 변경/삭제 **불가**
- `ticket_item_status`: `VALID` (기본) / 삭제 시 소프트 삭제

### 판매 기간
- `sale_start_at` ~ `sale_end_at`으로 판매 기간 제한
- `is_sellable` 플래그로 수동 판매 중지/재개

## 2. 발급 티켓 (IssuedTicket)

### 상태 머신

```
ENTRANCE_INCOMPLETE ──(QR 스캔)──► ENTRANCE_COMPLETED
        │                                │
        │                          (입장 취소)
        │                                │
        └──(주문 취소/환불)──► CANCELED   ◄─┘ (불가)
```

| 상태 | 코드 | 설명 |
|------|------|------|
| 입장 전 | `ENTRANCE_INCOMPLETE` | 발급 직후 |
| 입장 완료 | `ENTRANCE_COMPLETED` | QR 스캔으로 입장 처리 |
| 취소 | `CANCELED` | 주문 취소/환불 시 연동 |

### 발급 규칙
- 주문 확정(`DoneOrderEvent`) 시 **자동 발급**
- 1개 OrderLineItem → `quantity`만큼 IssuedTicket 생성
  - 예: 3장 주문 → IssuedTicket 3개 발급
- **입장 완료 티켓은 취소 불가** → `CanNotCancelException`
- 티켓번호: `"T" + (10000 + DB_ID)` (예: T10001)

### QR 입장 처리

#### 처리 플로우
```
카메라 QR 스캔 → UUID 추출 → PATCH /events/{eventId}/issuedTickets/{uuid}
```

#### IssuedTicketValidator 검증 규칙 (소스코드 기반)

> 소스: `DuDoong-Domain/.../issuedTicket/validator/IssuedTicketValidator.kt`

| # | 검증 | 실패 시 예외 |
|---|------|-------------|
| 1 | UUID로 발급 티켓 조회 | `IssuedTicketNotFoundException` |
| 2 | `issuedTicket.eventId == eventId` (이벤트 ID 교차 검증) | `IssuedTicketNotMatchedEventException` |
| 3 | `issuedTicketStatus.isAfterEntrance() == false` (중복 입장 차단) | `IssuedTicketAlreadyEntranceException` |
| 4 | `issuedTicketStatus.isCanceled() == false` (취소 티켓 차단) | `CanNotEntranceException` |
| 5 | 호스트 **매니저 이상** 권한 | `@HostRolesAllowed` AOP |

#### 입장 처리 코드
```kotlin
fun entrance() {
    if (issuedTicketStatus.isCanceled()) throw CanNotEntranceException.EXCEPTION
    if (issuedTicketStatus.isAfterEntrance()) throw IssuedTicketAlreadyEntranceException.EXCEPTION
    issuedTicketStatus = IssuedTicketStatus.ENTRANCE_COMPLETED
    enteredAt = LocalDateTime.now()
    Events.raise(EntranceIssuedTicketEvent.from(this))
}
```

#### 취소 처리 코드
```kotlin
fun cancel() {
    if (!issuedTicketStatus.isBeforeEntrance()) throw CanNotCancelException.EXCEPTION
    issuedTicketStatus = IssuedTicketStatus.CANCELED
}
```
→ `ENTRANCE_INCOMPLETE` 상태에서만 취소 가능 (입장 후 취소 불가)

#### 입장 취소
- `ENTRANCE_COMPLETED` → `ENTRANCE_INCOMPLETE` 복구 가능
- 입장 전 상태에서 입장 취소 시도 → `CanNotCancelEntranceException`

## 3. 옵션 시스템

### 3-레이어 구조

```
OptionGroup (옵션 그룹) ──── Event에 귀속
    └── Option (선택지)

ItemOptionGroup (티켓 ↔ 옵션그룹 연결) ──── TicketItem에 귀속

IssuedTicketOptionAnswer (주문 시점 스냅샷) ──── IssuedTicket에 귀속
```

### 옵션 유형

| 유형 | 코드 | 설명 |
|------|------|------|
| 객관식 | `SUBJECTIVE` | 미리 정의된 선택지 중 선택 |
| Y/N | `TRUE_FALSE` | 예/아니오 |
| 주관식 | `OBJECTIVE` | 자유 텍스트 입력 |

### 옵션 규칙
- 필수 옵션(`isEssential`) 미답변 시 주문 불가
- **무료 티켓에 유료 옵션(amount > 0) 적용 불가**
- 주문 시점에 답변이 **스냅샷으로 보존** (이후 옵션 변경에 영향 없음)
- 판매 이력이 있는 옵션 → 삭제/변경 불가

## 노션 가이드 참조

> 출처: [두둥 티켓 종류 및 유의사항](../public-notion/두둥-티켓-종류-및-유의사항.md)

### 두둥 티켓
- 주최자 통장에 직접 입금 → 주최자 승인으로 티켓 발급
- 승인 요청은 Slack 알림으로 수신 가능

### 무료 티켓
- **승인형**: 관리자가 수동 승인
- **선착순**: 즉시 발급

### 유료 티켓
- **제휴 호스트만** 사용 가능
- 토스페이먼츠 카드 결제

### 유의사항
- 환불 기한: 공연 시작 전까지
- 환불 수수료: 없음
