# 티켓 도메인 - UseCase 시나리오

## UC-T01: 티켓 상품 생성

**Actor**: 호스트 매니저 이상
**선행조건**: 이벤트 존재 (PREPARING 또는 OPEN)

### 정상 플로우
1. PayType + ApproveType 선택
2. 유효한 조합인지 검증
3. 가격, 수량, 판매기간, 구매제한 설정
4. 티켓 생성

### 예외 플로우
- PRICE_TICKET + APPROVAL → 불가능한 조합
- DUDOONG_TICKET + FIRST_COME → 불가능한 조합
- PRICE_TICKET인데 partner 호스트 아님 → 유료 티켓 생성 불가
- DUDOONG_TICKET인데 계좌 정보 미입력 → 생성 불가
- PRICE_TICKET인데 가격 < 1,000원 → 최소가격 미달

## UC-T02: QR 입장 처리

**Actor**: 호스트 매니저 이상 (현장 스태프)
**선행조건**: 이벤트 OPEN, 발급 티켓 존재

### 정상 플로우
1. QR 스캐너 앱에서 카메라로 QR 코드 스캔
2. UUID 추출
3. `PATCH /events/{eventId}/issuedTickets/{uuid}` 호출
4. 5가지 검증 통과
5. status → `ENTRANCE_COMPLETED`, `enteredAt` 기록
6. `EntranceIssuedTicketEvent` 발행 → Slack 알림

### 예외 플로우
- 다른 공연 QR → 이벤트 ID 불일치 → 차단
- 이미 입장한 티켓 → `IssuedTicketAlreadyEntranceException`
- 취소된 티켓 → `CanNotEntranceException`

### QR 스캐너 모드
> 출처: [입장 체크하기](../public-notion/입장-체크하기.md)
- 풀스크린 / 모바일 / 일반 / 웹 4가지 UI 지원
- 관객이 QR 코드를 미리 준비 (마이페이지 → 티켓 → QR)

## UC-T03: 입장 취소

**Actor**: 호스트 매니저 이상
**선행조건**: 이미 `ENTRANCE_COMPLETED` 상태

### 정상 플로우
1. 실수로 입장 처리된 티켓 선택
2. 입장 취소 → status: `ENTRANCE_INCOMPLETE`로 복구

### 예외 플로우
- 입장 전 상태에서 취소 시도 → `CanNotCancelEntranceException`

---

## UC-T04: 옵션 그룹 관리

**Actor**: 호스트 매니저 이상

### 생성 플로우
1. 옵션 그룹 생성 (이름, 유형, 필수 여부)
2. 옵션 항목 추가 (객관식의 경우)
3. 티켓에 옵션 그룹 적용 (ItemOptionGroup 연결)

### 규칙
- 무료 티켓에 유료 옵션 적용 불가
- 판매 이력 있는 옵션 삭제 불가
- 주문 시점에 스냅샷 저장 → 이후 옵션 변경해도 기발급 티켓에 영향 없음

## 문의 대응 가이드

### "QR이 안 찍혀요"
1. 티켓 상태 확인: `ENTRANCE_INCOMPLETE`인지
2. 이벤트 ID 일치 여부 확인
3. 관객에게 QR 새로고침 안내

### "입장 처리했는데 다시 입장 전으로 바꾸고 싶어요"
- 입장 취소 기능으로 `ENTRANCE_COMPLETED` → `ENTRANCE_INCOMPLETE` 복구 가능

### "티켓이 취소됐다고 나와요"
1. 주문 상태 확인 (REFUND/CANCELED)
2. 주문 취소/환불 시 발급 티켓도 자동 취소됨
