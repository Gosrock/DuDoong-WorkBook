# Decision Log Skill

## Purpose
프로덕트/정책 결정을 `decisions/README.md`에 DEC-NNN 형식으로 기록한다.
결정의 맥락(왜)과 대안(뭘 안 했는지)을 남겨서 나중에 "왜 이렇게 했지?" 할 때 찾을 수 있게 한다.

## When to Activate
- 유저가 "결정했어", "정책 정했어", "decision 기록해줘" 등을 말할 때
- 미결 사항 목록에서 결론이 난 항목이 생겼을 때
- 코드 분석을 통해 현재 구현 상태가 확인되어 정책으로 기록할 수 있을 때

## Workflow

1. **정보 수집**: 유저에게 다음을 확인한다
   - 결정 내용 (한 문장으로 요약)
   - 이유 (왜 이렇게 결정했는지)
   - 검토한 대안 (뭘 선택하지 않았는지, 없으면 "N/A")
   - 영향받는 태스크 (관련 태스크 ID, 없으면 "없음")
   - 참여자 (결정한 사람, 없으면 "팀 합의" 또는 "코드 분석 기반")

2. **DEC 번호 결정**: `decisions/README.md`의 기존 기록을 확인해서 다음 번호 할당
   - 형식: `DEC-001`, `DEC-002`, ... (3자리 zero-padding)

3. **decisions/README.md 업데이트**:
   - 기존 결정 목록 다음에 새 항목 추가
   - 포맷:
     ```markdown
     ## DEC-NNN: 제목

     - **일자**: YYYY-MM-DD
     - **결정**: (결정 내용)
     - **이유**: (왜 이렇게 결정했는지)
     - **대안**: (검토했지만 선택 안 한 것)
     - **영향**: (이 결정에 영향받는 태스크)
     - **참여자**: (결정에 참여한 사람)
     ```

4. **미결 사항 처리**: `decisions/README.md`의 `## 미결 사항` 섹션에서 해당 항목을 `- [ ]` → `- [x]`로 변경

5. **관련 태스크/에픽 연결 언급**: 관련 태스크가 있으면 해당 태스크 파일의 `## 참고` 섹션에 결정 번호 언급 제안

## Examples

```
유저: 카카오 로그인만 지원하기로 결정했어
→ DEC-001 생성: "카카오 단독 OAuth 지원"
  미결 사항에서 관련 항목 체크 처리

유저: MASTER 역할 이전 기능은 v2에서 구현하지 않기로 했어
→ DEC-002 생성: "MASTER 역할 이전 기능 현재 미지원 (v3 검토)"
  host 도메인 관련 미결 항목 체크 처리
```

## Notes
- 결정 파일 위치: `DuDoong-WorkBook/decisions/README.md`
- 결정 번호는 항상 3자리 (DEC-001, DEC-010, DEC-100)
- 코드 분석으로 확인된 사실을 기록할 때는 참여자를 "코드 분석 기반 (Claude)"으로 기재
- 미결 사항이 줄어드는 것이 목표 — 결정을 미루지 않고 기록하는 것을 장려
