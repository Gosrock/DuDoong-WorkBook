## CI/CD 파이프라인

### 이미지 빌드 (GitHub Actions)

**태그 컨벤션**:
| 서비스 | 태그 형식 | 예시 |
|--------|----------|------|
| Backend API | `Api-v*.*.*` | `Api-v1.0.7` |
| Backend Batch | `Batch-v*.*.*` | `Batch-v1.0.1` |
| Backend Socket | `Socket-v*.*.*` | `Socket-v1.0.1` |
| Frontend Ticket | `Ticket-v*.*.*` | `Ticket-v1.3.1` |
| Frontend Admin | `Admin-v*.*.*` | `Admin-v1.1.2` |

**백엔드 빌드**:
```
태그 push → GitHub Actions → Java 17 setup → Redis docker up (테스트) →
./gradlew :Module:build → Docker Hub push
```

**프론트엔드 빌드**:
```
태그 push → GitHub Actions → .env 생성 (Secrets) →
Docker Buildx (linux/amd64) → Docker Hub push
```

### 배포 (DuDoong-Deploy)

> **CI/CD는 DuDoong-Deploy 리포를 통해 운영 중**
> GitHub: https://github.com/Gosrock/DuDoong-Deploy

```
DuDoong-Deploy main push → deploy.yml →
.env 생성 → SSH 접속 → docker-install.sh →
rsync 파일 동기화 → docker-compose pull → up --build -d → prune
```

- 이미지 레지스트리: **Docker Hub** (ECR 아님)
- 시크릿 관리: GitHub Secrets → 배포 시 `.env` 파일 생성
- 배포 설정 파일: `docker-compose.prod.yml`, `docker-compose.staging.yml`, `nginx/`

## 배포 환경 재구성 시 체크리스트

스테이징 서버를 다시 올리거나, 새 환경을 구성할 때 필요한 작업:

### 1. EC2 인스턴스
- [ ] 인스턴스 생성 (t2.small 이상 권장, ap-northeast-2c)
- [ ] SG: 22, 80, 443 인바운드 허용
- [ ] SSH 키 페어 설정
- [ ] Docker + Docker Compose 설치 (`docker-install.sh`)

### 2. ALB 타겟 그룹
- [ ] 기존 TG `Dudoong-Staging`에 새 인스턴스 등록
- [ ] 또는 새 TG 생성 후 ALB 리스너 규칙 업데이트
- [ ] Health Check: `/api/v1/examples/health`

### 3. RDS 접근
- [ ] 새 EC2의 SG를 `dudoong-rds` SG 인바운드에 추가
- [ ] 또는 기존 `Dudoong-bound` SG 사용

### 4. 환경변수
- [ ] GitHub Secrets에서 `.env` 파일 생성 (또는 수동 복사)
- [ ] `SPRING_PROFILES_ACTIVE=staging`
- [ ] DB, Redis, OAuth, PG, AWS, Slack, NCP 키 설정

### 5. Docker Compose
- [ ] `docker-compose.staging.yml` 이미지 태그 업데이트
- [ ] `docker-compose pull && docker-compose up -d`

### 6. DNS (이미 설정됨)
- [x] `staging.dudoong.com` → ALB (Route 53 A 레코드 존재)

### 7. SSL (이미 설정됨)

## Dockerfile 구조

COPY build/libs/*.jar app.jar
ENTRYPOINT ["java", "-Dspring.profiles.active=${SPRING_PROFILES_ACTIVE}", "-jar", "app.jar"]
