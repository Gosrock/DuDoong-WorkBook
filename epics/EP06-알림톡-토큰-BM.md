# EP06: 알림톡 토큰 BM

## 개요

호스트가 토큰을 충전하고, 카카오 알림톡을 자유롭게 사용하는 수익화 모델.
PG 없이 계좌이체로 충전, 알림톡으로 발송. 두둥의 첫 번째 매출 채널.

> **API 전환**: NCP → [Sendon.io](https://sdk.sendon.io/reference/) (API v2)
> Backend 이슈: [Gosrock/DuDoong-Backend#699](https://github.com/Gosrock/DuDoong-Backend/issues/699)

## 배경

- 현재 두둥 매출: **0원** (중개 수수료 미확정, 제휴 호스트 알림톡은 무료 제공 중)
- 알림톡 인프라 이미 완성 (NcpHelper, 템플릿 3종, 이벤트 핸들러)
- 현재 제휴 호스트(`partner=true`)만 알림톡 사용 가능
- NCP 알림톡 원가: 건당 ~8원
- 호스트 1,171개, 이벤트 1,408개 — 잠재 고객 충분

## 토큰 충전 패키지

| 패키지 | 토큰 | 가격 | 건당 단가 |
|--------|------|------|----------|
| 베이직 | 100 | 5,000원 | 50원 |
| 프로 | 500 | 20,000원 | 40원 |

- 결제 방식: 계좌이체 → 관리자 확인 → 토큰 충전
- 마진율: 80~87% (원가 건당 ~8원)

## 토큰 소비 메뉴

| 기능 | 방향 | 설명 | 토큰 |
|------|------|------|------|
| 예매 완료 알림 | →관객 | 예매 확정 시 관객에게 카톡 | 1토큰/건 |
| 예매 취소 알림 | →관객 | 환불/취소 시 관객에게 카톡 | 1토큰/건 |
| 공지 발송 | →관객 | 호스트가 자유 내용 작성해서 관객에게 발송 | 1토큰/건 |
| 공연 홍보 | →이전 관객 | 이전 공연 관객에게 새 공연 안내 | 1토큰/건 |
| 예매/환불 접수 알림 | →호스트 | 예매 또는 환불 발생 시 호스트에게 카톡 | 1토큰/건 |

### 기능 상세

#### 관객 → 예매 완료/취소 알림 (기존 기능 확장)
- 현재: `host.isPartnerHost()` 체크 → 제휴 호스트만 발송
- 변경: `host.hasTokens() && eventSetting.enabled` → 토큰 있고 설정 켜져 있으면 발송
- 기존 NCP 템플릿 `doneorderv2`, `cancelorder` 그대로 사용

#### 관객 → 공지 발송 (신규)
- 호스트가 자유 내용 작성 → 해당 공연 예매 관객에게 일괄 발송
- NCP 템플릿: 변수형 범용 공지 템플릿 신규 등록 필요
- 템플릿 예시: `[#{호스트이름}] 공지\n#{자유내용}\n공연: #{공연이름}\n📅 #{날짜}`
- 용도: 장소 변경, 시간 변경, 리마인더, 안내사항 등 호스트 자유

#### 이전 관객 → 공연 홍보 (신규)
- 해당 호스트의 과거 공연 예매 관객에게 새 공연 안내
- 대상 자동 추출: 호스트의 이전 이벤트 → 확정 주문 → 유저 → 전화번호
- 발송 전 대상 수 + 필요 토큰 미리보기 제공
- NCP 템플릿: 홍보용 신규 등록 필요

#### 호스트 → 예매/환불 접수 알림 (신규)
- 예매 또는 환불 발생 시 호스트 멤버에게 카톡
- 호스트가 받을 사람 선택 가능 (방장, 매니저 등)
- 받는 사람 수 × 1토큰 소비
- NCP 템플릿: 접수 알림용 신규 등록 필요

## 운영 플로우

```
충전: 호스트 → 계좌이체 → 관리자 확인 → 토큰 충전
사용(자동): 호스트가 공연별 알림 ON → 이벤트 발생 시 자동 차감
사용(수동): 호스트가 공지/홍보 작성 → 대상 확인 → 발송 → 차감
잔액 부족: 발송 스킵 + Slack 웹훅으로 호스트에게 안내 (무료)
```

## 데이터 모델 (신규)

```
Host (기존 테이블 확장)
  └── tokenBalance: Long          ← 현재 잔액

TokenTransaction (신규)
  ├── id, hostId
  ├── type: CHARGE | CONSUME | REFUND
  ├── amount: Int                 ← +100 / -1
  ├── balance: Int                ← 거래 후 잔액
  ├── description: String
  ├── relatedEventId: Long?
  └── createdAt, createdBy

EventAlimTalkSetting (신규)
  ├── eventId
  ├── doneOrderEnabled: Boolean   ← 예매 완료 알림
  ├── withdrawOrderEnabled: Boolean ← 예매 취소 알림
  └── hostNotifyEnabled: Boolean  ← 예매/환불 접수 알림 (호스트)
```

## 알림톡 템플릿 작업

| 템플릿 | 상태 | 용도 |
|--------|------|------|
| `doneorderv2` | 기존 등록 완료 (NCP) → Sendon 재등록 필요 | 예매 완료 알림 |
| `cancelorder` | 기존 등록 완료 (NCP) → Sendon 재등록 필요 | 예매 취소 알림 |

| `hostnotice` | **신규 등록 필요** | 공지 발송 (변수형) |
| `promotion` | **신규 등록 필요** | 공연 홍보 |

## Sendon.io API 전환 계획

### 왜 NCP → Sendon?

- Sendon이 채널 관리, 템플릿 CRUD, 검수, 수신거부, 포인트 조회 등 **어드민에 필요한 API를 풍부하게 제공**
- NCP는 발송 위주 → 어드민에서 템플릿/채널 관리를 직접 할 수 없었음
- Sendon API v2 Base URL: `https://api.sendon.io`, 인증: HTTP Basic Auth + IP 화이트리스트

### 어드민 알림톡 관리 기능

#### 테스트 발송
- 템플릿 검수 전후 내부 번호로 테스트 메시지 발송
- 변수 치환 결과를 미리 확인하는 용도
- 검수 반려 방지를 위한 사전 검증 필수

#### 수기 발송 (공지사항 등)
- 어드민에서 대상자 지정 → 일괄 알림톡 발송
- 용도: 공연 일정 변경, 긴급 안내, 운영 공지 등
- 예약 발송 지원 (특정 시간 예약 + 취소 가능)
- 발송 후 그룹별/건별 결과 조회

#### 채널(발신프로필) 관리
- 채널 목록/상세 조회
- 신규 채널 등록 (인증 알림톡 → 토큰 입력 → 등록)

#### 템플릿 관리
- 템플릿 CRUD (생성, 조회, 수정, 삭제)
- 검수 요청 / 검수 취소
- 검수 상태 모니터링 (NEED_REVIEW → IN_REVIEW → APPROVED / REJECTED)

#### 이미지 업로드
- 알림톡 템플릿용 이미지 (최대 5MB, 최대 3개)
- 대체문자(MMS)용 이미지 (최대 300KB)

#### 수신거부 관리
- 수신거부 추가/조회/삭제

#### 포인트/충전금액 조회
- Sendon 계정 포인트 잔액 및 내역 조회
- 서비스 단가 조회 (알림톡/친구톡 등 메시지 타입별 건당 비용)
- 결제 내역 조회
- 발신번호 목록 조회

## 카카오 알림톡 템플릿 검수 가이드

> 템플릿은 카카오 검수 승인 후에만 발송 가능. **영업일 기준 1~3일** 소요.

### 검수 상태 흐름

```
생성 → NEED_REVIEW → (검수 요청) → IN_REVIEW → APPROVED (발송 가능)
                                             → REJECTED (수정 후 재검수)
장기 미사용 시 → DORMANT
```

### 템플릿 타입별 제약

| 메시지 타입 | 설명 | 글자수 |
|------------|------|--------|
| `BA` (기본형) | 본문만 | 1,000자 |
| `EX` (부가정보형) | 본문 + 부가정보 | 1,000자 + 500자 |
| `AD` (채널추가형) | 본문 + 채널추가 안내 | 1,000자 + 80자 |
| `MI` (복합형) | 본문 + 부가정보 + 채널추가 | 1,000자 + 500자 + 80자 |

| 강조 타입 | 필수 요소 | 제약 |
|----------|----------|------|
| `NONE` | 없음 | - |
| `TEXT` | Title + Subtitle (둘 다 필수) | Title: Android 23자/iOS 27자, Subtitle: Android 18자/iOS 21자 |
| `IMAGE` | 이미지 URL | 사전 업로드 필수 |
| `ITEM_LIST` | 아이템 리스트 | 상품/서비스 목록 |

### 버튼 규칙

- 최대 5개, `ordering`으로 순서 지정
- WL(웹링크): `urlMobile`, `urlPc` 필수
- AL(앱링크): `schemeAndroid`, `schemeIos` 지원
- BK(봇키워드), MD(메시지전달), DS(배송조회), AC(채널추가)

### 변수 규칙

- `#{변수명}` 형식 — 본문에서 사용, 발송 시 `variables`로 치환
- **부가정보(templateExtra)에서는 변수 사용 불가** — 고정 텍스트만

### 검수 통과 핵심 규칙

1. **정보성 메시지만 허용** — 사용자가 요청/동의한 정보 전달 목적만 가능
   - ✅ 허용: 주문확인, 배송안내, 예매완료, 일정변경, 결제내역
   - ❌ 불가: 할인 프로모션, 이벤트 홍보, 재구매 유도 → **광고성은 친구톡 사용**
2. **변수에 광고/홍보 문구 삽입 금지** — 변수 자리에 어떤 값이 들어가는지도 심사 대상
3. **발신자 정보 명시** — 누가 보내는 메시지인지 명확해야 함
4. **URL은 실제 서비스 관련만** — 외부 광고 링크, 리다이렉트 URL 금지
5. **템플릿 내용과 실제 발송 내용 일치** — 변수 치환 후 결과가 템플릿 의도와 달라지면 안 됨

### 반려 빈출 패턴

- 본문에 "할인", "특가", "이벤트 참여" 등 광고성 표현 포함
- 변수에 마케팅 메시지가 들어갈 수 있는 구조
- 버튼 URL이 프로모션/랜딩 페이지로 연결
- 발신 주체가 불명확
- 수신자가 요청하지 않은 정보 전달 구조

### DuDoong 템플릿 작성 시 주의사항

| 템플릿 | 검수 포인트 |
|--------|------------|
| `hostnotice` (공지 발송) | "공연 일정 변경", "장소 변경" 등 **정보 전달**로 작성. `#{자유내용}` 변수에 광고가 들어갈 수 있다고 판단되면 반려될 수 있음 → 변수 용도를 명확히 기술 |
| `promotion` (공연 홍보) | ⚠️ **알림톡으로는 검수 통과 어려움** — 홍보/마케팅 목적이므로 **친구톡(FriendTalk)** 사용 검토 필요 |
| `hostnotify` (예매/환불 접수) | 호스트에게 "예매 접수됨", "환불 요청됨" 사실 전달 → 검수 통과 가능성 높음 |
| `doneorderv2` (예매 완료) | 기존 NCP에서 승인된 패턴 그대로 → 검수 통과 가능성 높음 |
| `cancelorder` (예매 취소) | 기존 NCP에서 승인된 패턴 그대로 → 검수 통과 가능성 높음 |

> **중요**: `promotion` 템플릿은 알림톡 정책상 반려 가능성이 높음.
> 이전 관객 대상 홍보는 **친구톡** 또는 **문자(SMS/LMS)** 대체 방안을 함께 검토해야 함.

## 의사결정 기록

| 결정 | 내용 | 이유 |
|------|------|------|
| PG 없이 계좌이체 | 토큰 충전은 계좌이체 + 관리자 수동 확인 | PG 수수료 회피, 운영 초기 규모에 적합 |
| 1토큰 = 1건 통일 | 모든 알림톡 1건당 1토큰 | 단순함, 호스트가 계산하기 쉬움 |
| 공지 발송은 변수형 템플릿 | 카카오 심사된 템플릿 + 자유 내용 변수 | 호스트 자유도 확보 + 카카오 정책 준수 |
| D-1 리마인더 별도 기능 제외 | 공지 발송으로 흡수 | 배치잡 정액 과금이 애매, 공지로 같은 효과 |
| 관객 수신거부 기능 제외 | 초기 버전에서 제외 | 단순화 우선, 필요 시 추후 추가 |
