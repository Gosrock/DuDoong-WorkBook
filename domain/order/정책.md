# 주문/결제(Order) 도메인 정책

## 상태 머신

9개 상태, 11개 전이 규칙으로 구성됩니다.

```
                    ┌──────────────────────────────────────┐
                    │                                      │
              유료/무료선착순                          두둥/승인형
                    │                                      │
                    ▼                                      ▼
READY ──────► PENDING_PAYMENT                    PENDING_APPROVE
                    │                                      │
        ┌───────────┼────────────┐              ┌──────────┼──────────┐
        │           │            │              │                     │
  Toss확인     0원 무료확정    서버오류      관리자 승인          관리자 거절
        │           │            │              │                     │
        ▼           ▼            ▼              ▼                     ▼
     CONFIRM    APPROVED      FAILED        APPROVED             CANCELED
        │           │
        └─────┬─────┘
              │
     ┌────────┼────────┐
     │                  │
  사용자 환불      관리자 취소
     │                  │
     ▼                  ▼
   REFUND           CANCELED
```

| 상태 | 코드 | 설명 |
|------|------|------|
| 주문 생성 | `READY` | 초기 상태 (@PostPersist 직후) |
| 결제 대기 | `PENDING_PAYMENT` | 유료/무료 선착순 주문 |
| 승인 대기 | `PENDING_APPROVE` | 두둥티켓/승인형 주문 |
| 결제 완료 | `CONFIRM` | PG 결제 확인 완료 |
| 승인 완료 | `APPROVED` | 관리자 승인 or 무료 확정 |
| 환불 완료 | `REFUND` | 사용자 환불 |
| 취소됨 | `CANCELED` | 관리자 취소 or 거절 |
| 결제 실패 | `FAILED` | 서버 오류 |
| 만료됨 | `OUTDATED` | 결제 시간 초과 (배치 처리) |

---

## 결제 방식 라우팅

티켓의 `PayType` + `ApproveType` 조합에 따라 **자동** 결정됩니다.

| PayType | ApproveType | OrderMethod | 처리 방식 |
|---------|-------------|-------------|----------|
| `PRICE_TICKET` (유료) | `FIRST_COME` | `PAYMENT` | 토스페이먼츠 PG 결제 |
| `FREE_TICKET` (무료) | `FIRST_COME` | `PAYMENT` | `/free` 엔드포인트 즉시 확정 |
| `FREE_TICKET` (무료) | `APPROVAL` | `APPROVAL` | 관리자 승인 대기 |
| `DUDOONG_TICKET` (두둥) | `APPROVAL` | `APPROVAL` | 무통장입금 + 관리자 승인 |

## 주문 생성 시 검증 (6가지)

| # | 검증 항목 | 예외 |
|---|----------|------|
| 1 | 이벤트가 `OPEN` 상태인지 | 주문 불가 |
| 2 | 티켓팅 시간 내인지 (`now() < startAt`) | `EventTicketingTimeIsPassedException` |
| 3 | 재고 충분한지 (`supplyCount >= quantity`) | 재고 부족 |
| 4 | 한 종류 티켓만 주문하는지 | 혼합 구매 불가 |
| 5 | 1인당 구매 제한 이내인지 | 구매 제한 초과 |
| 6 | 옵션 답변이 유효한지 | 옵션 불일치 |

### 승인형 주문 추가 검증
- 대기 중인 주문까지 포함한 **보수적** 재고/구매제한 검사
- `validApproveOrderCreateTotalStock(order)` - 승인 대기 주문 재고 체크

## 동시성 제어

- **Redisson 분산락**: `userId` 기반으로 동일 사용자 동시 주문 차단
  - `@RedissonLock(LockName = "주문생성", identifier = "userId")`
- **결제 확인 시**: 토스페이먼츠에서 받은 금액과 주문 금액 일치 검증

---

## 주문 생성 경로 (3가지)

### Case 1: 일반 주문 (결제)
```
CreateOrderUseCase → CreateOrderService.withOutCoupon()
→ Order.createPaymentOrder(userId, cart, item, orderValidator)
→ status: PENDING_PAYMENT, method: PAYMENT
```

### Case 2: 쿠폰 적용 주문
```
CreateOrderUseCase → CreateOrderService.withCoupon()
→ Order.createPaymentOrderWithCoupon(userId, cart, item, coupon, orderValidator)
→ 쿠폰 최소 결제액 검증
→ status: PENDING_PAYMENT, method: PAYMENT
```

### Case 3: 승인 주문 (두둥 티켓)
```
ApproveOrderUseCase → OrderApproveService.execute()
→ Order.createApproveOrder(userId, cart, item, orderValidator)
→ status: PENDING_APPROVE, method: APPROVAL
```

---

## 결제 금액 계산

```
Supply Amount  = 상품 가격 합계 (티켓 가격 × 수량 + 옵션 추가금)
Discount Amount = 쿠폰 할인액
Payment Amount = Supply - Discount (실 결제 금액)
```

## 취소/환불 정책

### 3-way 분리

| 구분 | 주체 | 대상 상태 | 결과 상태 | 도메인 이벤트 |
|------|------|----------|----------|--------------|
| **Refund** (환불) | 사용자 | CONFIRM, APPROVED | REFUND | `WithDrawOrderEvent` |
| **Cancel** (취소) | 관리자 | CONFIRM, APPROVED | CANCELED | `WithDrawOrderEvent` |
| **Refuse** (거절) | 관리자 | PENDING_APPROVE | CANCELED | - |

### 환불 가능 조건
- **이벤트 시작 전**에만 환불/취소 가능 (`now() < event.startAt`)
- 취소 수수료 **없음**
- 사용자 본인 확인 (`validOwner`)

### 환불 시 자동 보상 트랜잭션 (`WithDrawOrderEvent` 처리)
1. 쿠폰 사용 복구 (`usage_status → false`)
2. 발급 티켓 취소 (`CANCELED`)
3. 재고 복구 (`supplyCount += quantity`)
4. 유료 주문의 PG 환불 (비동기)

### 결제 확인 실패 시 보상 트랜잭션
`ConfirmOrderFailHandler` → `AFTER_ROLLBACK` 단계:
1. 쿠폰 사용 취소
2. 발급 티켓 철회
3. PG 환불 요청

## 티켓별 환불 규정 (노션 가이드)

> 출처: [두둥 환불 규정 관련](../public-notion/두둥-환불-규정-관련.md)

| 티켓 종류 | 환불 방법 | 비고 |
|-----------|----------|------|
| 무료 티켓 | 마이페이지에서 직접 환불 | 공연 시작 전까지 |
| 유료 티켓 | 마이페이지에서 직접 환불 (PG 자동 환불) | 공연 시작 전까지 |
| 두둥 티켓 | 마이페이지에서 환불 요청 → **주최자에게 별도 연락하여 계좌 전달** | 주최자가 직접 환불 의무 |

> 공연이라는 상품의 특성상 공연이 종료되면 상품 가치가 소멸합니다.

## 주문번호 규칙

```
주문번호 = "R" + (NO_START_NUMBER + orderId)
예: order_id=1 → R10001
```

- `@PostPersist` 시점에 생성
- `CreateOrderEvent` 발행 → Slack 알림

---

## 핵심 상수

| 상수 | 값 | 설명 |
|------|---|------|
| NO_START_NUMBER | 10,000 | 주문번호 시작 오프셋 |
| 최소 결제금액 | 1,000원 | 유료 티켓 최소 가격 |
| 쿠폰 최소 주문금액 | 10,000원 | 기본값 |

---

## 도메인 이벤트

| 이벤트 | 발행 시점 | 처리 |
|--------|----------|------|
| `CreateOrderEvent` | 주문 영속화 시 (@PostPersist) | Cart 초기화, 재고 감소, Slack 알림 |
| `DoneOrderEvent` | 주문 완료 전이 시 | 발급 티켓 생성, 쿠폰 사용 처리 |
| `WithDrawOrderEvent` | 주문 철회 시 | PG 환불, 재고 복구, 쿠폰 복구 |
