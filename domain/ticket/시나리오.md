# 티켓 도메인 - 시나리오

## UC-T01: 티켓 상품 생성

**Actor**: 호스트 매니저 이상
**선행조건**: 이벤트 존재 (준비 중 또는 오픈 상태)

### 정상 플로우
1. 결제 방식 + 판매 방식 선택
2. 유효한 조합인지 검증
3. 가격, 수량, 판매기간, 구매제한 설정
4. 티켓 생성

### 예외 플로우
- 유료 티켓 + 승인형 → 불가능한 조합
- 두둥 티켓 + 선착순 → 불가능한 조합
- 유료 티켓인데 파트너 호스트가 아님 → 유료 티켓은 파트너 호스트만 생성할 수 있습니다
- 두둥 티켓인데 계좌 정보 미입력 → 계좌 정보를 먼저 등록해야 합니다
- 유료 티켓 가격이 1,000원 미만 → 최소 판매가격(1,000원)을 충족해야 합니다

## UC-T02: QR 입장 처리

**Actor**: 호스트 매니저 이상 (현장 스태프)
**선행조건**: 이벤트 오픈 상태, 발급 티켓 존재

### 정상 플로우
1. QR 스캐너 앱에서 카메라로 QR 코드 스캔
2. QR 코드에서 티켓 식별값 추출
3. `PATCH /events/{eventId}/issuedTickets/{uuid}` 호출
4. 5가지 검증 통과
5. 입장 완료 처리, 입장 시각 기록
6. Slack 입장 알림 발송

### 예외 플로우
- 다른 공연 QR → 이 공연의 티켓이 아닙니다
- 이미 입장한 티켓 → 이미 입장 처리된 티켓입니다
- 취소된 티켓 → 입장할 수 없는 티켓입니다

### QR 스캐너 모드
> 출처: [입장 체크하기](../public-notion/입장-체크하기.md)
- 풀스크린 / 모바일 / 일반 / 웹 4가지 UI 지원
- 관객이 QR 코드를 미리 준비 (마이페이지 → 티켓 → QR)

## UC-T03: 입장 취소

**Actor**: 호스트 매니저 이상
**선행조건**: 이미 입장 완료 상태

### 정상 플로우
1. 실수로 입장 처리된 티켓 선택
2. 입장 취소 → 입장 전 상태로 복구

### 예외 플로우
- 입장 전 상태에서 취소 시도 → 입장 완료된 티켓만 취소할 수 있습니다

---

## UC-T04: 옵션 그룹 관리

**Actor**: 호스트 매니저 이상

### 생성 플로우
1. 옵션 그룹 생성 (이름, 유형, 필수 여부)
2. 옵션 항목 추가 (객관식의 경우)
3. 티켓에 옵션 그룹 적용

### 규칙
- 무료 티켓에 유료 옵션 적용 불가
- 판매 이력 있는 옵션 삭제 불가
- 주문 시점에 옵션 내용 고정 저장 → 이후 옵션을 변경해도 기발급 티켓에 영향 없음

## 문의 대응 가이드

### "QR이 안 찍혀요"
1. 티켓이 입장 전 상태인지 확인
2. 해당 공연의 티켓인지 확인
3. 관객에게 QR 새로고침 안내

### "입장 처리했는데 다시 입장 전으로 바꾸고 싶어요"
- 입장 취소 기능으로 입장 완료 → 입장 전 상태로 복구 가능

### "티켓이 취소됐다고 나와요"
1. 주문 상태 확인 (환불 또는 취소 상태인지)
2. 주문 취소/환불 시 발급 티켓도 자동 취소됨
