# 유저/인증(User) 도메인 정책

## 로그인/회원가입

### 카카오 OAuth (단일 Provider)
- 인증 방식: **OIDC id_token** 서명 검증 (카카오 RSA Public Key)
- `id_token`에서 `sub`(oid) 추출하여 유저 식별
- 로그인/회원가입 모두 동일한 검증 경로

### 회원가입 플로우

```
카카오 인증 → id_token 검증 → 신규 유저 여부 확인
    ├── 기존 유저 → 로그인 (JWT 발급)
    └── 신규 유저 → 회원가입 폼 → 등록 → JWT 발급
```

### 회원가입 입력 정보

| 필드 | 필수 | 비고 |
|------|:----:|------|
| 이름 (name) | O | |
| 이메일 (email) | O | |
| 전화번호 (phoneNumber) | X | |
| 프로필 이미지 | X | |
| 마케팅 동의 (marketingAgree) | X | 기본값 false |

### 동시성 제어
- `@RedissonLock(LockName="유저등록", identifier="oid")`
- 동일 카카오 계정의 동시 가입 차단

## JWT 토큰 정책

### 토큰 구조

| 토큰 | 기본 TTL | 저장 위치 | 비고 |
|------|---------|----------|------|
| Access Token | 3600초 (1시간) | 쿠키 또는 Bearer 헤더 | `JWT_ACCESS_EXP`로 오버라이드 가능 |
| Refresh Token | 3600초 (1시간) | Redis (`@RedisHash`) | `JWT_REFRESH_EXP`로 오버라이드 가능 |

### 토큰 추출 우선순위
1. 쿠키 (`accessToken`) 우선 확인
2. `Authorization: Bearer` 헤더 fallback

### 쿠키 보안 설정

| 설정 | 값 |
|------|---|
| Secure | `true` (항상) |
| SameSite | prod: `Strict`, 개발: `None` |
| HttpOnly | **미적용** (주석 처리 상태) |

### 토큰 갱신
- Refresh Token으로 Access Token 재발급
- 갱신 시 `lastLoginAt` 업데이트

## 유저 상태 (AccountState)

| 상태 | 코드 | 로그인 | 설명 |
|------|------|:------:|------|
| 정상 | `NORMAL` | O | 기본 상태 |
| 탈퇴 | `DELETED` | X (403) | 탈퇴 처리됨 |
| 정지 | `FORBIDDEN` | X (403) | 영구 정지 |
| 일시정지 | `SUSPENDED` | - | 예약 상태 (로직 미구현) |

---

## 탈퇴 처리

### 3단계 프로세스
1. **Redis**: Refresh Token 삭제
2. **DB**:
   - `accountState` → `DELETED`
   - 프로필 마스킹: `name → "탈퇴한 유저"`, `email/phoneNumber/profileImage → null`
   - oid 변경: `DELETED:{timestamp}:{oid}` (재가입 대비)
3. **카카오**: `unlinkUser` API 호출 (카카오 연결 해제)

### 탈퇴 시 주의사항
- 승인 대기 중(`PENDING_APPROVE`) 주문 존재 시 → 승인 거부 처리

## 인가 체계

### 시스템 역할 계층 (AccountRole)

```
SUPER_ADMIN > ADMIN > MANAGER > USER
```

Spring Security `RoleHierarchy` 적용.

### API 접근 제어

| 분류 | 패턴 |
|------|------|
| **인증 불필요** | `/v1/auth/oauth/**`, `/v1/auth/token/refresh` |
| | `GET /v1/events/{id}` (이벤트 상세 조회) |
| | 이벤트 검색, 댓글 조회 |
| **USER 이상** | 나머지 모든 API |
| **SUPER_ADMIN** | `POST /v1/coupons/campaigns` (쿠폰 캠페인 생성) |

### 호스트 도메인 이중 인가

AccountRole과 별도로 **HostRole 계층** 적용:
```
MASTER > MANAGER > GUEST
```

`@HostRolesAllowed` AOP로 호스트 관련 API에 선언적 권한 검사.

## 알려진 보안 이슈

| 이슈 | 심각도 | 설명 |
|------|:------:|------|
| HttpOnly 쿠키 미적용 | **높음** | XSS로 토큰 탈취 가능 |
| Access/Refresh TTL 동일 | 중간 | 기본값 둘 다 1시간, Refresh가 더 길어야 실용적 |
| SUSPENDED 상태 미구현 | 낮음 | enum만 존재, 실제 로직 없음 |
