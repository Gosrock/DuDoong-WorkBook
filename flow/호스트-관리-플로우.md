# 호스트 관리 플로우

## 라우팅 구조 (admin 앱)

admin.dudoong.com 에서 호스트가 공연을 생성·관리하는 화면 구조다.

| 경로 | 화면 |
|------|------|
| `/` | 홈 (호스트 목록) |
| `/new/hosts` | 호스트 생성 |
| `/new/events` | 이벤트 생성 |
| `/hosts/{hostId}/dashboard` | 호스트 대시보드 |
| `/hosts/{hostId}/member` | 멤버 관리 |
| `/hosts/{hostId}/info` | 호스트 정보 |
| `/hosts/{hostId}/alliance` | 제휴 정보 |
| `/hosts/{hostId}/slack` | Slack 연동 설정 |
| `/events/{eventId}/dashboard` | 이벤트 대시보드 (통계) |
| `/events/{eventId}/detail` | 이벤트 상세 정보 |
| `/events/{eventId}/info` | 이벤트 기본 정보 |
| `/events/{eventId}/tickets` | 티켓 상품 관리 |
| `/events/{eventId}/options` | 옵션 그룹 관리 |
| `/events/{eventId}/guests` | 예매자 관리 |
| `/events/{eventId}/qr` | QR 스캐너 |

## 이벤트 생성 7단계

공연을 열기 위해 호스트가 순서대로 진행하는 흐름이다.
각 단계는 저장 후 다음 단계로 이동하며, 중간에 나가도 임시 저장된 내용이 유지된다.

### 1단계: 호스트 선택 또는 생성

기존 호스트가 있으면 선택하고, 없으면 새 호스트를 만든다.
- `POST /hosts` 로 호스트 생성

**실패 분기**

| 상황 | 사용자에게 보이는 것 | 처리 |
|------|------------------|------|
| 호스트 이름 미입력 | 입력 필드 아래 "호스트 이름을 입력해 주세요." 안내 | 다음 단계 진행 불가 |
| 저장 실패 | "저장에 실패했습니다. 다시 시도해 주세요." | 입력 내용 유지, 재시도 버튼 제공 |

---

### 2단계: 이벤트 기본 정보 입력

공연 이름, 날짜/시간, 러닝타임을 설정한다.
- `POST /events` 로 이벤트 생성

**실패 분기**

| 상황 | 사용자에게 보이는 것 | 처리 |
|------|------------------|------|
| 필수 항목(이름·시간) 미입력 | 해당 필드에 "필수 항목입니다." 안내 | 다음 단계 진행 불가 |
| 과거 날짜 입력 | "공연 날짜를 확인해 주세요." 안내 | 다음 단계 진행 불가 |
| 저장 실패 | "저장에 실패했습니다." | 입력 내용 유지, 재시도 버튼 제공 |

---

### 3단계: 장소 설정

카카오 맵 검색으로 공연 장소를 지정한다.

**실패 분기**

| 상황 | 사용자에게 보이는 것 | 처리 |
|------|------------------|------|
| 장소 미선택 | "장소를 선택해 주세요." 안내 | 다음 단계 진행 불가 |
| 카카오 맵 로딩 실패 | "지도를 불러올 수 없습니다." | 직접 입력 방식으로 대체 가능 여부 안내 |

---

### 4단계: 상세 정보 (포스터 + 공연 소개)

포스터 이미지를 업로드하고 공연 소개 본문을 작성한다.
이미지는 S3 Presigned URL을 통해 업로드된다.

**실패 분기**

| 상황 | 사용자에게 보이는 것 | 처리 |
|------|------------------|------|
| 이미지 용량/형식 오류 | "JPG, PNG 형식의 10MB 이하 이미지를 올려주세요." | 파일 선택 화면으로 복귀, 재업로드 가능 |
| 이미지 업로드 실패 (네트워크) | "이미지 업로드에 실패했습니다. 다시 시도해 주세요." | 이미지 선택 상태 유지, 재시도 버튼 제공 |
| 본문 미작성 상태 저장 | 경고 없이 저장 허용 (선택 항목) | 이후 공개 전 작성 권장 안내 |

---

### 5단계: 티켓 생성

결제 방식(유료 / 두둥 / 무료)과 승인 방식(선착순 / 승인)을 선택하고, 가격·수량·판매 기간을 설정한다.

**실패 분기**

| 상황 | 사용자에게 보이는 것 | 처리 |
|------|------------------|------|
| 필수 항목 미입력 | 해당 필드에 인라인 오류 안내 | 저장 불가 |
| 판매 종료일이 시작일보다 앞선 경우 | "판매 기간을 확인해 주세요." | 저장 불가 |
| 저장 실패 | "티켓 저장에 실패했습니다." | 입력 내용 유지, 재시도 버튼 제공 |

---

### 6단계: 옵션 생성 및 티켓에 적용

티켓에 추가 옵션(객관식 / Y/N / 주관식)을 생성하고 연결한다.
옵션이 없으면 이 단계를 건너뛸 수 있다.

**실패 분기**

| 상황 | 사용자에게 보이는 것 | 처리 |
|------|------------------|------|
| 옵션 항목 미입력 | "옵션 항목을 1개 이상 입력해 주세요." | 저장 불가 |
| 저장 실패 | "옵션 저장에 실패했습니다." | 입력 내용 유지, 재시도 버튼 제공 |

---

### 7단계: 이벤트 공개

모든 설정이 완료되면 공개 버튼을 눌러 이벤트를 오픈한다.
- `PATCH /events/{id}/open` 으로 공개 처리

**실패 분기**

| 상황 | 사용자에게 보이는 것 | 처리 |
|------|------------------|------|
| 필수 단계 미완료 | "티켓이 1개 이상 필요합니다." 등 미완료 항목 안내 | 해당 단계로 이동 유도 |
| 공개 처리 실패 | "공개에 실패했습니다. 잠시 후 다시 시도해 주세요." | 공개 버튼 재시도 가능 |

## 예매자(게스트) 관리

> 출처: [두둥 공연 관리하기](../public-notion/두둥-공연-관리하기.md)

### 승인 대기 탭

두둥 티켓(무통장입금) 방식의 예매 건을 확인하고 승인 또는 거절한다.

```
GET /events/{id}/orders?orderStage=APPROVE_WAITING
  → POST /events/{id}/orders/{uuid}/approve  (승인 → 티켓 발급)
  → POST /events/{id}/orders/{uuid}/refuse   (거절 → 예매자에게 거절 안내)
```

### 완료 탭

확정된 예매를 조회하고 필요 시 취소 처리한다.

```
GET /events/{id}/orders?orderStage=CONFIRMED
  → POST /events/{id}/orders/{uuid}/cancel   (취소 → 예매자에게 취소 안내)
```

### 예매 티켓 조회

- 발급된 티켓 목록 조회
- 입장 여부 확인

## QR 입장 처리

공연 당일, 호스트 또는 스태프가 QR 스캐너 화면에서 관객의 티켓을 스캔한다.

```
카메라 QR 스캔 → UUID 추출
  → PATCH /events/{eventId}/issuedTickets/{uuid}
  → 입장 상태 변경: 입장 전 → 입장 완료
```

스캐너 UI는 풀스크린 / 모바일 / 일반 / 웹 4가지 모드를 지원한다.

### 실패 분기

| 상황 | 호스트에게 보이는 것 | 처리 |
|------|------------------|------|
| QR 인식 실패 | "QR 코드를 인식하지 못했습니다." | 재스캔 안내, 또는 UUID 직접 입력으로 수동 처리 |
| 이미 입장 처리된 티켓 | "이미 입장한 티켓입니다." (경고음) | 입장 처리 없이 경고 표시 |
| 취소된 티켓 스캔 | "취소된 티켓입니다." (경고음) | 입장 불가 안내 |
| 다른 이벤트 티켓 스캔 | "이 공연의 티켓이 아닙니다." | 입장 불가 안내 |
| 네트워크 오류 | "네트워크 오류가 발생했습니다." | 재시도 안내, 오프라인 모드 여부 확인 |

## 주문 상태 흐름

예매 건이 가질 수 있는 상태와 전환 조건이다.

| 상태 | 의미 |
|------|------|
| 주문 생성 | 장바구니 생성 직후 |
| 결제 대기 | 결제창 열림, 입금 대기 |
| 승인 대기 | 두둥 티켓 입금 후 호스트 확인 대기 |
| 결제 시간 만료 | 결제 시간 초과 (OUTDATED) |
| 결제 완료 | 유료 결제 확정 |
| 승인 완료 | 호스트 승인 완료 → 티켓 발급 |
| 환불 완료 | 환불 처리 완료 |
| 취소된 결제 | 호스트 또는 시스템에 의해 취소 |
| 결제 실패 | 카드사 등 결제 수단 오류 |
