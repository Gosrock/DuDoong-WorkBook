# 티켓(TicketItem / IssuedTicket / Option) 도메인 정책

## 1. 티켓 상품

### 티켓 유형 매트릭스

3가지 지불 유형과 2가지 승인 유형의 조합에 엄격한 제약이 있습니다.

#### 지불 유형

| 유형 | 코드 | 가격 | 제약 |
|------|------|------|------|
| 무료 티켓 | `FREE_TICKET` | 0원 고정 | - |
| 유료 티켓 | `PRICE_TICKET` | 최소 1,000원 | 선착순 방식만 가능, **제휴(partner) 호스트 전용** |
| 두둥 티켓 | `DUDOONG_TICKET` | 자유 설정 | 승인 방식만 가능, **계좌 정보 필수 등록** |

#### 승인 유형

| 유형 | 코드 | 설명 |
|------|------|------|
| 선착순 | `FIRST_COME_FIRST_SERVED` | 결제 완료 시 즉시 확정 |
| 승인형 | `APPROVAL` | 호스트가 수동으로 승인해야 발급 |

#### 유효한 조합

| 지불 유형 | 승인 유형 | 가능 여부 | 비고 |
|-----------|-----------|:---------:|------|
| 무료 티켓 | 선착순 | O | 일반 무료 |
| 무료 티켓 | 승인형 | O | 관리자 승인 필요 |
| 유료 티켓 | 선착순 | O | **제휴 호스트 전용** |
| 유료 티켓 | 승인형 | X | 유료+승인 조합 불가 |
| 두둥 티켓 | 승인형 | O | **계좌 정보 필수** |
| 두둥 티켓 | 선착순 | X | 두둥+선착순 조합 불가 |

---

### 재고 관리

- 총 발행 수량과 남은 수량을 분리하여 관리합니다.
- 재고 차감은 주문 생성 시점에, 재고 복구는 주문 취소/환불 시점에 이루어집니다.
- 동시에 여러 사용자가 주문할 때 재고 초과를 방지하기 위해 티켓 아이템 단위 분산락이 적용됩니다.

### 구매 제한

- 1인당 최대 구매 수량을 설정할 수 있습니다.
- 검증 시 기존 주문 수량과 신규 주문 수량을 합산합니다.
- 승인형 주문은 승인 대기 중인 주문도 포함하여 보수적으로 검사합니다.

### 티켓 수정/삭제 제약

- 판매 이력이 있는 티켓은 옵션 변경 및 삭제가 불가합니다.
- 삭제 시 소프트 삭제 방식을 사용합니다.

### 판매 기간

- 판매 시작일과 종료일을 지정하여 판매 기간을 제한할 수 있습니다.
- 수동으로 판매를 중지하거나 재개할 수 있습니다.

## 2. 발급 티켓

### 상태 머신

```
입장 전 ──(QR 스캔)──► 입장 완료
   │                        │
   │                   (입장 취소)
   │                        │
   └──(주문 취소/환불)──► 취소됨  ◄─┘ (불가)
```

| 상태 | 코드 | 설명 |
|------|------|------|
| 입장 전 | `ENTRANCE_INCOMPLETE` | 발급 직후 기본 상태 |
| 입장 완료 | `ENTRANCE_COMPLETED` | QR 스캔으로 입장 처리됨 |
| 취소 | `CANCELED` | 주문 취소/환불 시 자동 연동 |

### 발급 규칙

- 주문이 최종 확정되는 시점에 **자동 발급**됩니다.
- 주문한 수량만큼 개별 티켓이 각각 발급됩니다.
  - 예: 3장 주문 → 발급 티켓 3개 생성
- 이미 입장 완료된 티켓은 취소할 수 없습니다. (이 경우 환불 자체가 불가능합니다.)
- 티켓 번호 형식: `"T"` + 오프셋(10,000) + DB ID (예: T10001)

---

### QR 입장 처리

#### 처리 흐름

```
카메라로 QR 스캔 → UUID 추출 → 입장 처리 API 호출
```

#### QR 입장 검증 규칙

스태프가 QR 코드를 스캔하면, 시스템은 다음 5가지를 순서대로 확인합니다.

1. **티켓이 존재하는가**: QR에 담긴 식별자로 발급 티켓을 조회합니다. 존재하지 않으면 잘못된 QR입니다.

2. **이 공연의 티켓이 맞는가**: 다른 공연의 QR 코드로 입장하는 것을 차단합니다. 예를 들어 A 공연 QR을 B 공연 입구에서 스캔하면 거부됩니다.

3. **이미 입장한 티켓이 아닌가**: 한 번 입장 처리된 티켓은 다시 입장할 수 없습니다. 중복 입장을 방지합니다.

4. **취소된 티켓이 아닌가**: 환불이나 취소로 무효화된 티켓은 입장할 수 없습니다.

5. **스태프 권한이 있는가**: QR 입장 처리는 해당 호스트의 **매니저 이상** 역할만 가능합니다.

#### 입장 취소

실수로 입장 처리한 경우, 입장 완료 상태에서 다시 입장 전 상태로 되돌릴 수 있습니다. 반대로 아직 입장하지 않은 티켓에 대해 입장 취소를 시도하면 거부됩니다.

#### 티켓 취소

주문이 환불/취소되면 해당 주문에서 발급된 모든 티켓이 자동으로 취소됩니다. 단, **이미 입장 완료된 티켓은 취소할 수 없습니다**. 이 경우 환불 자체가 불가능합니다.

#### 입장 관련 에러 메시지

| 상황 | 원인 | 대응 |
|------|------|------|
| "다른 공연의 QR입니다" | 공연 불일치 | 올바른 공연 입구에서 스캔 안내 |
| "이미 입장 처리된 티켓입니다" | 중복 스캔 | 이미 입장했음을 안내 |
| "취소된 티켓입니다" | 환불/취소된 주문의 티켓 | 유효한 티켓인지 확인 안내 |

## 3. 옵션 시스템

### 3계층 구조

```
옵션 그룹 (공연에 귀속)
    └── 선택지 (옵션)

티켓-옵션그룹 연결 (티켓 상품에 귀속)

주문 시점 옵션 답변 스냅샷 (발급 티켓에 귀속)
```

### 옵션 유형

| 유형 | 코드 | 설명 |
|------|------|------|
| 객관식 | `MULTIPLE_CHOICE` | 미리 정의된 선택지 중 하나를 선택 |
| Y/N 선택 | `TRUE_FALSE` | 예 또는 아니오 선택 |
| 주관식 | `SUBJECTIVE` | 자유 텍스트 입력 |

### 옵션 규칙

- 필수 옵션에 답변하지 않으면 주문할 수 없습니다.
- 무료 티켓에는 추가 금액이 있는 옵션을 적용할 수 없습니다.
- 주문 시점의 답변은 **스냅샷으로 영구 보존**됩니다. 이후 옵션 구성이 변경되어도 기존 주문의 답변 기록에는 영향을 주지 않습니다.
- 판매 이력이 있는 옵션은 삭제하거나 변경할 수 없습니다.

### 두둥 티켓
- 주최자 통장에 직접 입금 후 주최자 승인으로 티켓 발급
- 승인 요청은 Slack 알림으로 수신 가능

### 무료 티켓
- **승인형**: 관리자가 수동 승인
- **선착순**: 즉시 발급

### 유료 티켓
- **제휴 호스트만** 사용 가능
- 토스페이먼츠 카드 결제

### 유의사항
- 환불 기한: 공연 시작 전까지
- 환불 수수료: 없음
